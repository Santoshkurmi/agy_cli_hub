## 1. Core Architecture: The Generic Step Format

In modern AGY Hub, tool invocations do **not** arrive as top-level fields (e.g. `step.runCommand` is usually `null` or absent at the root level). Instead, the model's tool calls are wrapped inside **`CORTEX_STEP_TYPE_GENERIC`**:

```json
{
  "type": "CORTEX_STEP_TYPE_GENERIC",
  "status": "CORTEX_STEP_STATUS_DONE",
  "metadata": {
    "toolCall": {
      "id": "call_252245",
      "name": "run_command"
    },
    "toolAction": "Checking Python version",
    "toolSummary": "Check Python version",
    "sourceTrajectoryStepInfo": {
      "stepIndex": 16,
      "trajectoryId": "db7e9c01-e515-4f1b-947f-03ec4b6dbe63"
    }
  },
  "generic": {
    "args": { ... },
    "result": {
      "fullOutputUri": "file:///path/to/output.txt",
      "payload": { ... }
    }
  }
}
```

### Where Everything Lives:
1. **Tool Name:** `step.metadata.toolCall.name` (fallback: `step.metadata.toolSummary`)
2. **Tool Call ID:** `step.metadata.toolCall.id` (unique call identifier, e.g. `call_252245`)
3. **Action Description:** `step.metadata.toolAction` (user-friendly label, e.g. `"Checking Python version"`)
4. **Input Arguments:** `step.generic.args` (key-value map of parameters generated by the model)
5. **Execution Output:** `step.generic.result.payload` (embedded step object containing typed result)
6. **Large Output File:** `step.generic.result.fullOutputUri` (local file URI if stdout/content was truncated)

## 2. Step Lifecycle & State Transitions

Every tool step transitions through a deterministic lifecycle indicated by the `status` field:

```
                      ┌──────────────────────────────────────┐
                      │     CORTEX_STEP_STATUS_WAITING        │  (Requires Permission/Approval)
                      └──────────────────┬───────────────────┘
                                         │ User approves
                                         ▼
┌────────────────────────────────────────────────────────────┐
│      CORTEX_STEP_STATUS_PENDING / STATUS_RUNNING           │  (Active Execution)
└──────────────────────────────┬─────────────────────────────┘
                               │
               ┌───────────────┴───────────────┐
               ▼                               ▼
┌──────────────────────────────┐ ┌───────────────────────────┐
│   CORTEX_STEP_STATUS_DONE    │ │  CORTEX_STEP_STATUS_ERROR │
│ (Success: result.payload)    │ │ (Failure: step.error)     │
└──────────────────────────────┘ └───────────────────────────┘
```

| Status String | Meaning | UI State | Where to Read |
|---|---|---|---|
| `CORTEX_STEP_STATUS_WAITING` | Waiting for user interaction or permission | **Prompt User** (Allow / Deny buttons) | `step.requestedInteraction.permission` |
| `CORTEX_STEP_STATUS_PENDING` | Model emitted the tool call; about to execute | **Loading Spinner** | `step.generic.args` |
| `CORTEX_STEP_STATUS_RUNNING` | Tool is actively executing locally or in cloud | **Running / Progress** | `step.generic.args` |
| `CORTEX_STEP_STATUS_DONE` | Tool finished execution successfully | **Completed / Green check** | `step.generic.result.payload` |
| `CORTEX_STEP_STATUS_ERROR` | Tool failed or command exited with error | **Error / Red badge** | `step.error.shortError`, `step.error.fullError` |

## 3. Universal Extraction Pattern

To reliably handle any tool in both legacy and modern AGY Hub formats:

```typescript
function extractToolCall(step) {
  const meta = step.metadata || {};
  const toolCall = meta.toolCall || {};
  const generic = step.generic || {};
  const args = generic.args || {};
  const result = generic.result || {};
  const payload = result.payload || {};

  // 1. Tool Name
  const name = toolCall.name || meta.toolSummary || step.type;

  // 2. Lifecycle Status
  const status = step.status; // WAITING, PENDING, RUNNING, DONE, ERROR
  const isWaiting = status === 'CORTEX_STEP_STATUS_WAITING' || Boolean(step.requestedInteraction);
  const isRunning = status === 'CORTEX_STEP_STATUS_RUNNING' || status === 'CORTEX_STEP_STATUS_PENDING';
  const isDone = status === 'CORTEX_STEP_STATUS_DONE';
  const isError = status === 'CORTEX_STEP_STATUS_ERROR';

  // 3. User Action Label
  const label = meta.toolAction || args.toolAction || meta.toolSummary || name;

  // 4. Output / Result
  const errorMsg = step.error?.shortError || step.error?.message;
  const fullOutputUri = result.fullOutputUri;

  return { name, label, status, isWaiting, isRunning, isDone, isError, args, payload, errorMsg, fullOutputUri };
}
```

## 4. Tool-by-Tool Specification

### 1. `run_command`
Executes a terminal/shell command on the user's system via bash.

* **Tool Name:** `"run_command"`
* **Input Arguments (`generic.args`):**
  * `CommandLine` (string): The shell command string (e.g. `"python3 --version && which python3"`).
  * `Cwd` (string): Working directory path.
  * `IsDaemon` (string `"true"` | `"false"`): Whether it runs in background indefinitely.
  * `WaitMsBeforeAsync` (string / int): Milliseconds to wait before detaching.
* **Output / Result (`generic.result.payload.runCommand`):**
  * `combinedOutput.full` (string): Raw stdout + stderr combined.
  * `exitCode` (number): Process exit code (`0` for success).
* **Live JSON Example:**
```json
{
  "metadata": { "toolCall": { "name": "run_command" }, "toolAction": "Checking Python version" },
  "generic": {
    "args": { "CommandLine": "python3 --version" },
    "result": {
      "payload": {
        "runCommand": {
          "commandLine": "python3 --version",
          "exitCode": 0,
          "combinedOutput": { "full": "Python 3.14.7\r\n" }
        }
      }
    }
  }
}
```

### 2. `search_web`
Searches the live web using Google search.

* **Tool Name:** `"search_web"`
* **Input Arguments (`generic.args`):**
  * `query` (string): The search query (e.g. `"2026 web development trends"`).
* **Output / Result (`generic.result.payload.searchWeb`):**
  * `summary` (string): High-level synthesized summary of web results.
  * `results` (array): Array of `{ title, url, snippet }`.
* **Live JSON Example:**
```json
{
  "generic": {
    "args": { "query": "2026 web development trends", "toolAction": "Searching the web" },
    "result": {
      "payload": {
        "searchWeb": {
          "query": "2026 web development trends",
          "summary": "Key trends for web development in 2026 include AI agentic UI...",
          "results": [{ "title": "Web Trends 2026", "url": "https://example.com" }]
        }
      }
    }
  }
}
```

### 3. `view_file`
Reads contents and line ranges from local text or binary files.

* **Tool Name:** `"view_file"`
* **Input Arguments (`generic.args`):**
  * `AbsolutePath` (string): Full path to file (e.g. `"/home/cat/project/index.html"`).
  * `StartLine` (number, optional): 1-indexed start line.
  * `EndLine` (number, optional): 1-indexed end line.
* **Output / Result (`generic.result.payload.viewFile`):**
  * `content` (string): File text slice returned.
  * `numLines` (number): Number of lines in file.
* **Live JSON Example:**
```json
{
  "generic": {
    "args": { "AbsolutePath": "/home/cat/project/index.html", "StartLine": 1, "EndLine": 50 },
    "result": {
      "payload": {
        "viewFile": {
          "content": "<!DOCTYPE html>\n<html>\n...",
          "numLines": 25
        }
      }
    }
  }
}
```

### 4. `write_to_file`
Creates new files or overwrites existing files.

* **Tool Name:** `"write_to_file"`
* **Input Arguments (`generic.args`):**
  * `TargetFile` (string): Full path of file to create.
  * `CodeContent` (string): Content to write.
  * `Overwrite` (boolean): Whether to overwrite if file exists.
  * `Description` (string): Summary of why the file was written.
* **Output / Result (`generic.result.payload.codeAction`):**
  * `diffStats` (object): `{ additions, deletions }`.
  * `diff` (string): Unified diff generated.

---

### 5. `replace_file_content`
Performs surgical, contiguous search-and-replace edits on an existing file.

* **Tool Name:** `"replace_file_content"`
* **Input Arguments (`generic.args`):**
  * `TargetFile` (string): Target file path.
  * `TargetContent` (string): Exact lines of code to find and replace.
  * `ReplacementContent` (string): New code to substitute in place.
  * `StartLine` & `EndLine` (numbers): Search bounding lines.
* **Output / Result (`generic.result.payload.codeAction`):**
  * `diff` (string): Unified diff block.
  * `diffStats`: `{ additions: 1, deletions: 1 }`.

---

### 6. `list_dir`
Lists all children files and subdirectories of a directory.

* **Tool Name:** `"list_dir"`
* **Input Arguments (`generic.args`):**
  * `DirectoryPath` (string): Absolute directory path.
* **Output / Result (`generic.result.payload.listDirectory`):**
  * `results` (array of objects):
    * `name` (string): Filename or dirname.
    * `isDir` (boolean): `true` for directories.
    * `sizeBytes` (string): Size in bytes.

---

### 7. `grep_search`
Fast pattern and regex matching in files using ripgrep.

* **Tool Name:** `"grep_search"`
* **Input Arguments (`generic.args`):**
  * `Query` (string): Search query or regex.
  * `SearchPath` (string): Directory or file path to search.
  * `CaseInsensitive` (boolean): Case sensitivity flag.
* **Output / Result (`generic.result.payload.grepSearch`):**
  * `results` (array): Array of matches containing `{ fileName, lineNumber, lineContent }`.

---

### 8. `find_by_name`
Finds files by glob pattern matching (e.g. `*.py`, `*.kt`).

* **Tool Name:** `"find_by_name"`
* **Input Arguments (`generic.args`):**
  * `Pattern` (string): Glob pattern (e.g. `"*.txt"`).
  * `SearchDirectory` (string): Search root path.
* **Output / Result (`generic.result.payload.find`):**
  * `truncatedOutput` (string): List of matched file paths separated by newlines.

---

### 9. `read_url_content`
Fetches and converts public web page content to markdown via HTTP GET.

* **Tool Name:** `"read_url_content"`
* **Input Arguments (`generic.args`):**
  * `Url` (string): Target HTTP/HTTPS URL.
* **Output / Result (`generic.result.payload.readUrlContent`):**
  * `content` (string): Rendered markdown / text content.

---

### 10. `generate_image`
Generates images using Imagen / Google Gemini image models.

* **Tool Name:** `"generate_image"`
* **Input Arguments (`generic.args`):**
  * `Prompt` (string): Image description prompt.
  * `ImageName` (string): Desired output name.
  * `AspectRatio` (string): e.g. `"1:1"`, `"16:9"`, `"9:16"`.
* **Output / Result (`generic.result.payload.generateImage`):**
  * `generatedMedia.uri` (string): Local file URI where image is saved (`file:///path/to/image.jpg`).
  * `generatedMedia.inlineData` (string, optional): Base64 encoded image bytes.
  * `generatedMedia.mimeType` (string): e.g. `"image/jpeg"`.

---

### 11. `call_mcp_tool`
Calls a tool on a connected Model Context Protocol (MCP) server.

* **Tool Name:** `"call_mcp_tool"`
* **Input Arguments (`generic.args`):**
  * `ServerName` (string): Name of registered MCP server (e.g. `"dummy-mcp"`).
  * `ToolName` (string): Tool function name (e.g. `"dummy_greeting"`).
  * `Arguments` (object): Arguments dictionary passed to MCP server.
* **Output / Result (`generic.result.payload.mcpTool`):**
  * `result` (object / array): Content objects returned by the MCP server (`[{ type: "text", text: "..." }]`).

---

### 12. `list_resources` & 13. `read_resource`
Discovers and reads MCP server resource registries.

* **Input Arguments:** `ServerName` (string), `Uri` (string).
* **Output:** `payload.listResources` / `payload.readResource.contents`.

---

### 14. `manage_task`
Manages background CLI daemon tasks.

* **Tool Name:** `"manage_task"`
* **Input Arguments:** `Action` (`"list"` | `"status"` | `"kill"` | `"send_input"`), `TaskId`.
* **Output:** `generic.result.fullOutputUri` or status message.

---

### 15. `invoke_subagent`, 16. `define_subagent`, 17. `manage_subagents`
Spawns and manages autonomous subagents that work concurrently on delegated tasks.

* **`invoke_subagent` Args:** `Subagents: [{ description, name, prompt }]`.
* **Output:** `payload.invokeSubagent` with conversation IDs and status.

---

### 18. `send_message`
Sends cross-agent communication messages to active subagents.

* **Args:** `Recipient` (agent conversation ID), `Message` (string).

---

### 19. `schedule`
Schedules a one-shot background timer or recurring cron job.

* **Args:** `DurationSeconds` (number), `Prompt` (notification text), `TimerCondition` (`"never"` | `"any"`).

## 5. Permissions & User Interaction (`WAITING` State)

When a tool requires confirmation (e.g. MCP execution, external network requests, or dangerous shell commands), AGY sets:
* `step.status = "CORTEX_STEP_STATUS_WAITING"`
* `step.requestedInteraction`:
```json
{
  "requestedInteraction": {
    "type": "USER_INTERACTION_TYPE_CONFIRMATION",
    "permission": {
      "resource": {
        "action": "mcp",
        "target": "dummy-mcp/dummy_greeting"
      },
      "actionDescription": "Calling dummy_greeting on dummy-mcp server"
    }
  }
}
```

### How to Resolve / Approve in Client:
To allow the tool to proceed, send a request to `/exa.language_server_pb.LanguageServerService/ConfirmUserInteraction` or send interaction response with:
```json
{
  "cascadeId": "...",
  "stepIndex": 80,
  "permission": { "allow": true, "scope": "PERMISSION_SCOPE_ONCE" }
}
```

## 6. Pagination, History (Chunk 0) & Rollbacks (Undo)

### Initial Sync (Chunk 0)
When establishing a connection (`StreamAgentStateUpdates`):
1. **Frame 1 (Chunk 0)** delivers historical state.
2. If trajectory length is large (e.g. >50 steps), AGY paginates:
   * `pageBounds: { startIndex: 76 }`
   * `totalLength: 143`
   * `steps: [...]` (contains steps from `startIndex` to `totalLength - 1`).
   * `indices: [76, 77, 78, ...]`

### Handling Undo / Rollback
When the user clicks "Undo" or reverts a turn:
1. `totalLength` decreases in subsequent chunks.
2. Steps at or after the rollback index are invalidated.
3. The client must truncate its local message/tool list to `totalLength` or replace steps based on incoming `indices`.

## 7. Reference Implementation

### Kotlin (`AgyHubClient.kt` for Android)

```kotlin
fun extractToolCallFromStep(step: JSONObject, fallbackIndex: Int, conversationId: String): ToolCall? {
    val meta = step.optJSONObject("metadata")
    val toolCallMeta = meta?.optJSONObject("toolCall")
    val toolName = toolCallMeta?.optString("name", "") ?: ""
    val toolId = toolCallMeta?.optString("id", "tool_${conversationId}_$fallbackIndex") ?: ""

    val generic = step.optJSONObject("generic")
    val args = generic?.optJSONObject("args")
    val resultPayload = generic?.optJSONObject("result")?.optJSONObject("payload")

    // Determine tool type
    val recognizedName = when {
        toolName.isNotBlank() -> toolName
        args?.has("CommandLine") == true || step.has("runCommand") -> "run_command"
        args?.has("query") == true || step.has("searchWeb") -> "search_web"
        args?.has("AbsolutePath") == true || step.has("viewFile") -> "view_file"
        args?.has("TargetFile") == true -> "write_to_file"
        args?.has("DirectoryPath") == true || step.has("listDirectory") -> "list_dir"
        args?.has("Prompt") == true || step.has("generateImage") -> "generate_image"
        else -> return null
    }

    // Extract command or primary target
    val command = when (recognizedName) {
        "run_command" -> args?.optString("CommandLine", "") ?: ""
        "search_web" -> args?.optString("query", "") ?: ""
        "view_file" -> args?.optString("AbsolutePath", "") ?: ""
        "write_to_file", "replace_file_content" -> args?.optString("TargetFile", "") ?: ""
        "list_dir" -> args?.optString("DirectoryPath", "") ?: ""
        "generate_image" -> args?.optString("Prompt", "") ?: ""
        "call_mcp_tool" -> "${args?.optString("ServerName")}/${args?.optString("ToolName")}"
        else -> meta?.optString("toolAction", "") ?: ""
    }

    // Extract output
    val output = when (recognizedName) {
        "run_command" -> resultPayload?.optJSONObject("runCommand")?.optJSONObject("combinedOutput")?.optString("full", "") ?: ""
        "search_web" -> resultPayload?.optJSONObject("searchWeb")?.optString("summary", "") ?: ""
        "view_file" -> resultPayload?.optJSONObject("viewFile")?.optString("content", "") ?: ""
        "write_to_file", "replace_file_content" -> resultPayload?.optJSONObject("codeAction")?.optString("diff", "") ?: ""
        "call_mcp_tool" -> resultPayload?.optJSONObject("mcpTool")?.opt("result")?.toString() ?: ""
        else -> ""
    }

    val stepStatus = step.optString("status", "")
    val status = when {
        stepStatus == "CORTEX_STEP_STATUS_WAITING" || step.has("requestedInteraction") -> "PENDING_APPROVAL"
        stepStatus == "CORTEX_STEP_STATUS_RUNNING" || stepStatus == "CORTEX_STEP_STATUS_PENDING" -> "RUNNING"
        stepStatus == "CORTEX_STEP_STATUS_DONE" -> "SUCCESS"
        stepStatus == "CORTEX_STEP_STATUS_ERROR" -> "FAILED"
        else -> "RUNNING"
    }

    return ToolCall(
        id = toolId,
        name = recognizedName,
        command = command,
        output = output,
        status = status
    )
}
```
